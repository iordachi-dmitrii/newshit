# Док 2. Dynamic Workflows в Claude Code

> Выверено по `code.claude.com/docs/en/workflows` + блог Anthropic (июнь 2026).
> Источник-вдохновитель: тред «How to master Dynamic Workflows» (@0xCodez).

## Что это

Dynamic workflow — **JavaScript-скрипт, который Claude пишет под твою задачу** и который рантайм исполняет в фоне, пока сессия остаётся свободной. План переезжает из контекста в код: скрипт держит цикл, ветвления и промежуточные результаты, а в контекст Claude попадает только финал.

- Research preview. Требует **Claude Code v2.1.154+**.
- Доступно на всех платных планах + Anthropic API + Bedrock/Vertex/Foundry. На Pro включается в `/config` (строка Dynamic workflows).

## Когда брать workflow (а когда нет)

| | Subagents | Skills | Agent teams | **Workflows** |
| :-- | :-- | :-- | :-- | :-- |
| Кто решает, что дальше | Claude по ходу | Claude по промпту | Lead-агент | **Скрипт** |
| Где промежуточные результаты | контекст | контекст | общий task-list | **переменные скрипта** |
| Масштаб | пара задач/ход | то же | горстка пиров | **десятки–сотни агентов** |
| Прерывание | рестарт хода | рестарт хода | пиры работают | **resume в той же сессии** |

Бери workflow, когда агентов больше, чем один контекст способен скоординировать, или когда нужна **повторяемая** оркестрация как читаемый скрипт. Если обычная сессия справится за 5 минут — workflow не нужен.

## Как запустить

- Ключевое слово **`ultracode`** в промпте → Claude пишет workflow для этой задачи.
  (До v2.1.160 ключевым словом было `workflow`; запрос «своими словами» — «use a workflow» — работает всегда.)
- `/effort ultracode` → режим `xhigh` + авто-оркестрация: Claude сам решает, когда задача достойна workflow (на каждую существенную задачу в сессии). Сбрасывается со стартом новой сессии.
- Снять подсветку ключевого слова: `Option+W` (mac) / `Alt+W` (Win/Linux).
- Bundled workflow: **`/deep-research <вопрос>`** — fan-out веб-поиска → перекрёстная проверка источников → голосование по claim'ам → отчёт со ссылками.

## Approval и наблюдение

- Перед запуском — экран с фазами: **Yes, run it / Yes, don't ask again / View raw script / No**. `Ctrl+G` — открыть скрипт в редакторе.
- Поведение по permission mode: Default/acceptEdits — каждый раз; Auto — только первый запуск (при ultracode не спрашивает); Bypass/`claude -p`/SDK — без вопросов.
- Субагенты workflow **всегда работают в `acceptEdits`** и наследуют твой allowlist. Файловые правки авто-аппрувятся; shell/web/MCP вне allowlist всё равно могут спросить.
- `/workflows` — список и прогресс (фазы, число агентов, токены, время). Клавиши: `p` пауза/resume, `x` стоп, `r` рестарт агента, **`s` сохранить**.

## Лимиты рантайма

- **До 16 одновременных агентов** (меньше на слабом CPU).
- **Максимум 1000 агентов на запуск.**
- **Нет ввода пользователя в середине запуска** (для sign-off между стадиями делай каждую стадию отдельным workflow).
- Сам скрипт не имеет прямого доступа к ФС/shell — действуют агенты, скрипт их координирует.

## Resume (важная поправка к исходной статье)

- Resume работает **только внутри той же сессии**: уже завершённые агенты отдают кэш, остальные доделываются.
- ❗️**Если выйти из Claude Code, следующая сессия запустит workflow с нуля** (не «продолжит», как утверждала статья).

## Паттерны (как способ мышления)

| Паттерн | Суть | Когда |
| :-- | :-- | :-- |
| Classify-and-act | классификатор решает тип → роутинг | разнородные задачи; дорогую модель только где надо |
| Fan-out-and-synthesize | по агенту на пункт параллельно → слить (барьер) | перечислимый список независимых пунктов |
| Adversarial verification | отдельный агент-проверяльщик судит чужой результат по рубрике | фикс self-preference: автор ≠ судья |
| Generate-and-filter | сгенерить много → отфильтровать по рубрике | «решить поздно», после челленджа всех вариантов |
| Tournament | попарные сравнения вместо абсолютных оценок | сортировка 1000+; вкусовые решения |
| Loop-until-done | спавнить агентов до стоп-условия | неизвестный объём работы (флейки, баг-хант) |

Соответствие «провал → паттерн»: дрейф цели → fan-out; self-preference → adversarial verification; open-ended → loop-until-done; трудно оценить → tournament.

Реальный workflow обычно **композирует 2–4 паттерна** (миграция = fan-out → adversarial → loop; deep research = fan-out → проверка claim'ов → synthesize).

## Контроль стоимости

- Прогон тратит заметно больше токенов. Гонять сначала на узком срезе (одна директория, узкий вопрос).
- Каждый агент использует модель сессии, если скрипт не направит стадию на другую. Проверь `/model` перед большим прогоном; проси Claude брать модель поменьше для простых стадий.
- Пара с `/goal` — жёсткое условие завершения; с `/loop` — гонять весь workflow по расписанию.

## Сохранение и переиспользование

- `/workflows` → выбрать прогон → **`s`**. Сохранить в `.claude/workflows/` (проект) или `~/.claude/workflows/` (личный).
- Сохранённый workflow становится **slash-командой** `/<name>` (а не Skill с `SKILL.md` — поправка к статье).
- Принимает вход через глобал **`args`** (структурированные данные).
- Скрипт каждого прогона пишется в файл в `~/.claude/projects/...` — можно прочитать, сравнить, отредактировать и перезапустить.

## Отключение

`/config` (Dynamic workflows off) · `"disableWorkflows": true` в settings.json · `CLAUDE_CODE_DISABLE_WORKFLOWS=1`.

## ❌ Мифы и ошибки исходной статьи

- «terminal quit → resume продолжит» — **неверно**, стартует с нуля.
- «Core API `agent()/parallel()/pipeline()`» — **в официальной доке таких имён функций нет** (подавать как API нельзя).
- «per-agent isolation: worktree/remote» — **не подтверждается** страницей workflows.
- «Anthropic переписала Bun с Zig на Rust этим паттерном» — **почти наверняка выдумка** (Bun — сторонний проект).
- «Ship as Skill / SKILL.md» — сохранённый workflow это **команда**, не Skill.
- Числа токенов и дата «May 28» — непроверяемо.
